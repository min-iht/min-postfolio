# fluid zoom 분모에 inset과 스크롤바 폭이 빠져 잘림이 남던 문제

- 날짜: 2026-07-16
- 맥락: Portfolio 노트북 폭 보정 — rightUI 앵커 수식을 폐기하고 `#works`의 비례 수식 `tan(atan2(100vw, 1920px))`을 `#cv`/`#info`(css/cv.css, css/info.css)에도 적용하는 작업
- 태그: css-zoom, atan2, media-query, scrollbar, viewport

## 문제

시안 캔버스가 1920px이므로 `zoom: min(0.8, tan(atan2(100vw, 1920px)))`이면 어떤 폭에서도 잘리지 않아야 했는데, 1440px에서 cv의 `cv_box`가 화면 오른쪽 밖(1631px)까지 나갔다. zoom은 계산대로 0.75가 적용되어 있었기 때문에 수식 오타나 미디어쿼리 미적용은 아니었다.

## 시도한 것들 (실패 포함)

1. 분모 1920으로 적용 → cv가 1440에서 191px 잘림. "시안 = 1920이니 콘텐츠도 1920 안"이라는 가정이 틀렸음을 확인.
2. computed zoom·stylesheet 검사 → 수식은 정상 적용. 캐시 문제(navigate가 옛 CSS를 씀)는 `fetch(url, {cache:'reload'})` + reload로 별도 해소 — 브라우저 미리보기에서 CSS 수정 직후 computed 값이 안 변하면 코드보다 캐시부터 의심.
3. 실효 오른쪽 끝을 JS로 실측(`maxRight ÷ zoom`) → cv 2175px, info 1997px. 범인은 `--inset_left`(cv 240px / info 80px)가 `margin-left`에 더해져 콘텐츠를 시안 캔버스 밖으로 밀어낸 것.
4. 분모를 실측값(2176/2000)으로 교체 → 그래도 5~6px 잘림. `100vw`는 세로 스크롤바를 포함하는데 실제 콘텐츠 영역(clientWidth)은 스크롤바만큼 좁기 때문. 분모에 여유를 더해(2190/2010) 해결.

## 통한 접근법

분모를 "시안 폭"이 아니라 **실측한 실효 오른쪽 끝 + 스크롤바 여유**로 잡는다. 실측은 브라우저에서 섹션 내 모든 후손의 `getBoundingClientRect().right` 최댓값(단, `overflow-x`가 visible이 아닌 조상 안에 있는 요소는 의도된 클리핑이므로 제외)을 현재 zoom으로 나눈 값. 검증도 스크린샷 대신 같은 좌표 스캔으로 하면 잘림·겹침을 수치로 확정할 수 있다 (스크린샷 도구가 죽었을 때의 대안 경로이기도 했다).

## 일반화된 교훈

1. **비례 zoom을 걸었는데도 오른쪽이 잘리면, 콘텐츠의 실효 오른쪽 끝부터 실측하라** — 시안 캔버스 폭을 분모로 믿지 말 것. inset/margin 계열 변수 하나가 캔버스를 조용히 넘겨 놓았을 수 있다.
2. **`100vw` 기반 맞춤 수식은 세로 스크롤바 폭(~7px)만큼 항상 과대 측정한다** — 오른쪽 끝을 화면에 딱 맞추는 계산이면 분모에 1% 안팎의 여유를 더하라.
3. **CSS 수정 후 computed 값이 안 바뀌면 캐시부터** — `fetch(url, {cache:'reload'})` 후 reload로 확정하고 나서 코드를 의심하라.

## 재발 방지 (선택)

cv.css/info.css의 미디어쿼리 주석에 "inset이나 오른쪽 끝 요소를 옮기면 분모도 갱신"을 명시해 두었다. 분모의 유래(실측값 + 여유)도 주석에 있어 다음 조정 때 재실측 절차를 알 수 있다.
